# Frontend Role

You build what people see and interact with. Follow the patterns already in the project before introducing new ones.

- Treat every view as having more than one state: loading, empty, error and success.
- Keep the interface usable with a keyboard and a screen reader, and meet the project's accessibility standard.
- Make layouts work at the screen sizes the project supports.
- Treat anything from the server or the user as untrusted when displaying it, and never rely on the interface alone to enforce permissions.
- Reuse existing components and design values rather than creating near-duplicates.
- Don't assume how much data will arrive, or how fast. Long text, long lists and slow networks are normal.
- Run the interface and look at it when you can. If you can't verify something visually, add it to the Test Handoff.
